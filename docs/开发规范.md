# 个人办公台开发规范

## 原则与边界

极致轻量，极致简约。以可持续维护和真实个人使用为依据，不为新增一个页面引入独立 Web 运行时、后台常驻服务或通用框架。保持原生 egui 界面，模型进程按需加载。

## 代码分层

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 程序入口 | `main.rs` | 参数、进程入口、启动界面 |
| 应用编排 | `app.rs` | 状态构造、后台消息、工作区路由、退出保存 |
| 功能界面 | `app/*_ui.rs` | 当前功能的显示、交互和状态，不直接执行 SQL |
| 导航与外观 | `app/navigation_ui.rs`、`app/appearance.rs` | 统一导航和样式配置 |
| 领域规则 | `reference.rs`、`study.rs`、`curriculum.rs` 等 | 模型、验证和业务规则，避免依赖 UI 状态 |
| 数据库 | `db.rs`、`db/*.rs` | 建表、索引、事务和版本兼容；SQL 只在此层维护 |
| 共享组件 | `ui_components/` | 行列几何、导航、操作按钮等确实复用的界面组件 |
| 输出与更新 | `export.rs`、`updater.rs`、`install.rs` | 一致快照、原子输出、可恢复更新 |

新功能采用独立领域文件、数据访问文件和界面状态，避免继续扩充主文件中的大型业务块。相关规则放在所属模块，避免为了减少行数把不相关逻辑塞进 `utils`。现有模块只在有明确收益时拆分，保持行为和数据兼容。

## 持久化与升级

- 新表和新列采用增量升级，保留旧记录和未知设置；不得以清库重建解决版本问题。
- 多表写入放在事务内。用户编辑失败时保留草稿，界面只在提交成功后更新已保存状态。
- 内置数据有稳定 ID 和版本标记。导入与标记遵循可重放原则，同 ID 不覆盖个人修改；删除内置指令保留墓碑，后续升级不会复活。
- 可并行编辑的数据使用修订号检测冲突，不让旧界面覆盖较新的内容。历史练习快照保持不可变。
- 新模块必须进入模块导出和全部导出。快捷路径只保存地址，不能递归打包它们指向的外部文件夹。
- 真实数据验证先建立一致快照并检查完整性，升级和导出验收在副本上执行；更新包只替换程序。

## 指令条目规范

初始语言为 JavaScript、Java、C、C++、Rust、Go、Linux、MySQL。分类按用途组织，如基础语法、集合与容器、函数与对象、异常与资源、异步与并发、查询与聚合。用户可增加语言与分类，不把分类写死为只能选择初始值。

每条包含稳定 ID、语言、分类、类型、标签、名称、说明、语法、示例、要点和参考链接。基础示例以 Java 17、C17、C++17、Rust 2024、Go、现代 JavaScript、GNU/Linux、MySQL 8.0+ 为主要语境；特殊版本前提写在要点。示例多数是使用片段，按要点补充导入、外围函数或示例表；不能声称所有片段都可单独运行。

示例及中文解释为项目编写，参考链接指向语言/工具维护者文档。集合说明应交代顺序、空值、所有权或迭代失效等相关条件。SQL 与 Linux 命令只用于查阅和复制，指令页不执行命令。

## 性能约定

- egui 每帧不重复加载题库 JSON、整份正文、照片原件或数据库列表。查询结果缓存需与搜索、筛选和写入操作一致失效。
- 大列表仅绘制可见行。保留完整滚动高度，控件使用稳定记录 ID，滚动离屏不会丢弃编辑草稿。
- 内置数据只在首次或新版本导入；菜单只查所需字段。局部配置读取使用单键接口，不反复读取整份设置。
- 指令全文索引使用 SQLite FTS5 trigram；三个及以上字符走索引，较短关键字按字面量匹配；多个关键字取交集。显示列表只取摘要，选中后才读完整条目。
- 文件、网络、模型等耗时工作放后台，并有界面状态反馈；不要用长时间阻塞等待冻结界面。
- 性能结论附工作量、构建模式和对照方法；普通自动测试验证可见行数量、最后一行可达与数据一致性，避免断言某个机器耗时阈值。

## 界面与交互

遵循现有浅色风格、紧凑工具栏和固定操作区。列表的表头、文字及操作按共用几何对齐；不使用不同页各自凑内边距的方法。分类与搜索组合生效，空结果应可清空筛选。未保存编辑不能因为切换条目而被静默丢弃。

## 检查与发布

提交前执行：

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

测试使用临时目录和模拟数据。新增持久化模块至少覆盖增删改查、搜索/分类、重启、升级不覆盖、导出以及失败保留原数据。交互修复使用实际鼠标/键盘事件验证。模型、JDK、安装更新和性能测试按需显式运行，不把忽略项算作普通回归通过。

发布更新前检查新页面在 1000×680 与常用窗口尺寸的预览，构建正式版，在旧数据副本完成升级和完整导出核对，再发布带版本与哈希的更新包。保留运行中的旧程序，由用户点击更新；源码、文档与测试一起提交，推送后核对远程提交。

## 新功能接入清单

1. 定义独立模型与输入验证，选择明确的存储边界。
2. 增量建表/索引，编写事务、版本标记及冲突策略。
3. 在 `Section`、视图键、导航和工作区路由中接入；功能状态归入自己的模块。
4. 接入搜索、导出、空状态和已有快捷键，保留个人数据与草稿。
5. 添加行为回归、必要的性能验证、界面预览及 README 使用说明。

## 知识点专项与发布包

知识点通过稳定编号关联题目，不使用标题相似度猜测。新增标签不重写历史快照，推荐工程主线与基础语法专项区分。游戏棋盘与规则独立于界面；成绩追加持久化，最近缓存淘汰不删除完整历史。实现约定见 [知识点与游戏扩展](知识点与游戏扩展.md)。

安装包只包含经过验证的程序载荷，不包含个人数据或模型；脚本按 Cargo 版本生成清单与哈希，GitHub Release 标签应与源码提交一致。安装及卸载必须验证保留外部数据目录。
