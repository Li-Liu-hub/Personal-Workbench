维护入口：`./scripts/verify.ps1`。测试在临时目录、临时数据库、模拟记录或隔离子进程中运行；不会打开个人数据库、启动真实模型、播放声音或修改真实自启动项。

## 专用环境验证

普通回归中的 `ignored` 项必须单列，不能加入“已通过”数量。它们包含 Spark/GPU、Kokoro/音频播放、TinyCC/JDK、Typst 字体和人工性能测量；另有两个供其他测试启动的隔离子进程夹具。

需要本机模型或工具的测试，在准备好相应环境后按测试名显式执行，例如：

```powershell
cargo test every_reference_program_really_compiles_and_passes_all_samples -- --ignored --nocapture
cargo test live_resident_worker_reuse_cancel_and_restart -- --ignored --nocapture
cargo test actual_typst_renders_literal_user_content_and_multiple_pages -- --ignored --nocapture
```

这些命令必须使用与普通检查相同的 Rust 环境和 ASCII 构建目录；模型、字体、JDK 的路径及实测范围须另行记录。安装器的真实安装/卸载检查位于 `.github/workflows/package-release.yml`，发布动作不在普通质量检查中执行。

`excel-merge-tool/` 是保留的旧来源参考，当前桌面程序不编译或调用它；维护和测试目标为 `src/excel_merge*` 的内置实现。模型安装、打包和发布脚本也不在普通回归中下载资源、发布更新或更改安装状态。
