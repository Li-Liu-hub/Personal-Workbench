# Rust 个人办公台开发文档

版本 V1.3
日期 2026 年 10 月 20 日
目标平台 Windows 10 与 Windows 11 的 x64 桌面环境
文档用途 产品需求、技术设计、开发拆分与验收依据

本项目以一个本地桌面窗口集中管理常用账号、工作目录和日常文档。核心实现采用 Rust，界面采用 egui 与 eframe，数据保存在本机。启动后直接进入办公台，不要求创建应用账号、登录或输入主密码；再通过明确的接口扩展文档格式、搜索来源和平台能力。

本文件定义 V1 产品需求与工程约束。第 19 节记录当前源代码已经实现的行为、验证结果和仍未覆盖的项目。文中的性能数字是待测试的验收目标，不是已完成软件的实测结果。

## 1 产品目标与范围

### 1.1 需求对应关系

| 编号 | 用户需求 | V1 对应能力 | 关键验收结果 |
| --- | --- | --- | --- |
| R01 | 使用 Rust 开发 | Rust 原生桌面程序，以模块划分界面、数据、旧版迁移、文件和文档能力 | 业务、存储、系统适配和界面均有清楚边界 |
| R02 | 账号密码管理 | 平台账号密码库，不设置办公台登录、用户权限或主密码 | 密码按普通文本保存并始终直接显示，可编辑和复制 |
| R03 | 搜索 | 搜索结果融入账号、快捷路径、文档、物品等各自功能页 | 不设置独立搜索结果页；当前模块的内容随搜索词筛选 |
| R04 | 选择路径保存快捷入口 | 系统路径选择器、图文卡片、持久化、失效提示 | 重启后卡片保留；点击文件夹卡片进入办公台内的内容浏览 |
| R05 | 在办公台访问与操作文件夹 | 内置文件浏览、创建、重命名、复制、移动、回收站删除 | 操作作用于真实文件，结果与资源管理器一致 |

| R08 | 个人物品清单 | 记录物品名称、分类、数量、位置和备注 | 支持新增、编辑、删除及按条目字段搜索 |

### 1.2 默认产品决策

“账号密码管理”指保存网站、软件等平台的登录信息。办公台以使用方便为优先，不设置登录、权限校验、账号加密、密码隐藏、自动隐藏或锁定；账号信息保存在普通 SQLite 表中。仅在升级兼容时读取旧版加密文件，不创建新密钥。

“操作文件夹”包含内置文件列表和常见文件操作，不能仅实现一组打开资源管理器的按钮。资源管理器打开能力仍然保留，供用户使用完整系统功能。

文档写作直接在办公台可视化界面内完成。点击添加立即打开空白编辑区，填写标题和正文，程序自动分配内部文件标识并保存到自管 documents 目录；创建流程不弹出路径、文件名或格式选择框。标题属于数据库元数据，不作为实际文件路径，所以允许同名或包含路径特殊字符。需要单独文件时再主动导出文本或包含正文的 Word 副本；V1 不实现完整 Word 富文本排版引擎。

### 1.3 首版之外的范围

云同步、多设备冲突合并、多人权限、应用登录、浏览器自动填充、OCR、AI 写作、PDF 全文解析、Excel 在线编辑、任意第三方动态插件均不在当前范围。普通文档和外部文件夹以普通文件保存。

## 2 核心使用流程

### 2.1 首次启动与日常使用

1. 打开本机普通数据库，直接进入快捷路径页，无需创建应用账号或登录。
2. 新版账号按普通文本保存，不生成密钥，不依赖解锁流程。
3. 自动迁移本机可读取的旧版账号并保留原文件；无法读取旧文件时提示，不阻止新版本使用。
4. 点击账号方块即可查看、编辑和复制密码；密码始终显示，没有显示/隐藏开关或计时器。

### 2.2 添加快捷目录并使用

1. 在快捷路径页点击顶部“添加快捷路径”按钮或末尾“点击添加快捷路径”方块，再选择文件夹或文件。
2. 保存后快捷路径页都以带图形封面的卡片显示名称、路径和类型。
3. 点击文件夹卡片进入办公台内置文件浏览页，可新建、重命名、复制、移动或移入回收站。
4. 需要完整系统功能时，可选择“在资源管理器打开”；文件快捷入口会使用系统关联程序。
5. 原路径失效时卡片显示状态；移除入口只删除快捷记录，不删除目标文件或文件夹。

### 2.3 快速创建与编辑文档

1. 在文档页点击顶部“新建文档”或末尾“点击添加文档”方块，直接打开程序内的空白编辑窗口。
2. 在窗口内填写文档标题、编写正文，无需选择本机路径、文件名、格式或模板。
3. 程序使用唯一内部文件名保存正文，SQLite 保存独立标题，支持同名文档。
4. 停止输入约 2 秒后自动保存，也可点“保存”或 Ctrl+S；下次点击方块继续编写，标题和正文保持一致。
5. 台内文档保存后自动更新标题与正文搜索索引；索引失败不回滚已保存正文。
6. 只有主动点击“导出文本副本”或“导出 Word 副本”时才选择文件位置；导出保留台内原稿，也支持导出发生冲突时尚未写回的编辑内容。

### 2.4 查找并继续工作

顶部搜索框随时可用，输入内容后会在当前功能页筛选对应记录：账号页匹配名称、用户名和网址，快捷路径页匹配入口和已索引文件，文档页匹配文档记录及已索引正文，物品页匹配名称、分类、位置和备注。按 Enter 或点“查找”会执行已索引文件内容检索；匹配内容显示在所属功能内，不另开搜索结果页。账号密码本身不参与搜索。

## 3 界面与交互设计

### 3.1 主界面布局

应用没有工作台或首页，启动进入快捷路径页。左侧保留快捷路径、账号密码、文档写作、物品清单、网站收藏和设置。顶部保留当前模块搜索框、“查找”、“导出”和上下文添加按钮，Ctrl+N 与当前模块添加按钮执行相同动作。

账号、快捷路径、文件夹内容、文档和物品列表全部使用同一方块组件。每个方块等宽等高，在当前可用宽度内自动换行；标题和说明最多显示一行并省略长文本，悬停显示完整内容，不能因路径过长改变方块尺寸或把文字挤成竖排。

每个可添加内容的列表末尾始终显示“点击添加账号 / 快捷路径 / 文件夹 / 文档 / 物品”方块。顶部添加入口与末尾添加方块共用相同处理逻辑，空列表仍显示添加方块。

### 3.2 查看与编辑

左键点击账号或物品方块打开详情窗口，填写或修改后保存。密码始终以明文显示，不提供隐藏选项或自动隐藏。账号详情字段各占一整行，正文和输入内容使用 16 点字号与高对比颜色，字体启用像素网格对齐。文档列表显示全部已登记文档；新建文档直接打开台内编辑窗口，提供标题和正文、自动保存、冲突检查以及主动导出副本；原先登记的外部 Markdown/TXT 仍可台内编辑，旧 DOCX 文件使用系统关联程序打开。恢复草稿同样以方块显示，点击恢复为新文件。

点击快捷文件夹在台内进入其内容网格，点击子文件夹继续进入；工具条提供所有快捷路径、上一级、刷新、资源管理器打开和索引更新。设置页使用信息方块打开数据位置和使用说明。

### 3.3 右键管理与删除

账号和物品方块右键菜单提供删除记录。快捷入口右键“删除快捷入口”仅移除数据库记录及该来源的派生索引，保留目标文件夹和原文件。文档及真实文件方块右键删除送入系统回收站；回收站失败时保留原件并显示错误，不执行永久删除。文档删除后同步清理列表与派生搜索索引。文件夹内容的右键菜单另提供重命名、复制到、移动到。

关闭有未保存内容的文档编辑窗口前先尝试保存；冲突或保存失败时保留编辑窗口与恢复草稿。切换模块时清除旧模块搜索词和旧结果，搜索结果直接混排在所属功能的方块列表中。

## 4 技术选型

### 4.1 建议技术栈

| 领域 | 采用方案 | 选择理由与约束 |
| --- | --- | --- |
| 核心语言 | Rust stable，Edition 2024 | 开工时固定 rust-toolchain.toml 与最低支持版本 |
| 原生界面 | egui 与 eframe | 界面和业务均使用 Rust，适合本地工具 [S1] |
| 数据存储 | rusqlite 与随程序构建的 SQLite | 单机部署简单；确认启用 FTS5，提交 Cargo.lock |
| 文件选择 | rfd | 提供原生文件和目录选择器 [S2] |
| 搜索 | SQLite FTS5 trigram 与参数化 LIKE | 三字符以上正文索引与短词回退分开处理 [S3] |
| 系统集成 | windows-sys 与平台端口 | 关联打开、文件句柄与文件替换；DPAPI 仅用于读取旧版账号 |
| 文件监视与回收站 | notify 与 trash，封装在适配器中 | 监视失败可重扫；回收站失败不退化为永久删除 [S7] |
| 后台任务 | 标准线程与有界消息队列 | 无网络服务时不为形式引入完整异步运行时 |
| 文档与错误 | serde、thiserror、tracing | JSON 元数据、类型化错误和脱敏日志 |

本方案不依赖浏览器壳，也不要求用户安装 Rust。第三方库版本、feature、许可证与 Rust 版本兼容性在技术验证阶段确认，文档不凭空锁定未经验证的版本组合。

### 4.2 发布前的技术验证

先制作最小验证程序，确认 eframe 在目标电脑可启动、中文显示和输入法正常、rfd 可选中文路径、SQLite 可创建 trigram FTS5 表。验证系统关联打开、回收站删除、文件被 Word 占用时的报错，并验证空白 DOCX 可在目标 Word 或 WPS 打开。通过后再扩展业务界面。

若默认图形后端在目标驱动存在兼容性问题，评估 eframe 支持的备用后端，并记录验证结果；不能把“支持某后端”写成“已兼容所有显卡”。

## 5 架构与工程组织

### 5.1 依赖方向

UI 调用应用用例，应用用例使用领域模型和端口接口；适配器实现端口，桌面启动器负责组装。领域层不依赖 egui、SQLite 或 Windows API。模块边界先保持清晰，不拆成多个服务。

```text
desk-desktop  -> desk-ui
desk-desktop  -> desk-adapters
desk-ui      -> desk-application -> desk-domain
desk-adapters -> desk-application + desk-domain

UI: pages, view state, commands
Application: use cases, ports, session policy, jobs
Domain: entities, value objects, business rules
Adapters: SQLite, filesystem, crypto, Windows, document formats
Desktop: startup, dependency wiring, packaging
```

用户界面只提交命令和消费结果，不直接执行 SQL、不直接删除文件、不自行解密密码。用例校验输入与路径边界，再调用端口，最后返回可展示的结果；办公台不维护登录会话或应用权限。

### 5.2 建议目录

```text
personal-desk/
  Cargo.toml
  Cargo.lock
  rust-toolchain.toml
  crates/
    desk-domain/src/{vault,shortcut,document,error}.rs
    desk-application/src/{ports,use_cases,jobs}/
    desk-adapters/src/{sqlite,filesystem,crypto,windows,formats}/
    desk-ui/src/{pages,components,state,commands}/
    desk-desktop/src/main.rs
  migrations/
  tests/{integration,fixtures}/
  assets/
  packaging/windows/
  docs/
```

目录中的大括号是规划缩写，不表示真实文件名。模块不允许以一个跨层的 utils.rs 承载数据库、加密和界面逻辑。

### 5.3 关键模块职责

AccountService 负责普通账号增删改查，旧版迁移独立在 legacy_credentials 模块。ShortcutService 管理快捷入口。FileService 执行文件系统操作。DocumentService 管理创建、编辑状态与恢复。SearchService 汇总索引和当前模块筛选。

服务不实现“是否已登录”或角色权限判断。公共错误类型至少包含 InvalidInput、NotFound、PermissionDenied、Conflict、PathOutOfScope、StorageBusy、IoFailed、CryptoFailed 和 Cancelled。

### 5.4 后台任务与过期结果

UI 主线程只负责绘制和轻量状态更新。文件扫描、复制、密码派生、数据库慢查询和备份进入工作线程；建议初始工作线程数为 2 至 4，使用有界队列和背压，数值在验证后调整。

每个任务携带 job_id、cancellation_token 和必要的 query_revision。快速连续输入时旧搜索结果不得覆盖新查询；任务取消或失败后应销毁其临时敏感缓冲。

SQLite 写连接由单独写入队列管理，读连接独立使用；连接不跨线程无约束共享。事务内不等待文件拷贝或界面确认。支持 WAL、foreign_keys 与有限 busy_timeout，遇到持续锁定返回可重试错误 [S8]。

## 6 本地账号管理与旧版迁移

### 6.1 直接使用

账号与其他办公资料一样保存在本机。应用不实现登录、权限验证、加密写入、锁定或密码隐藏；保存、查看和复制均可直接完成。文档冲突检查、原子保存和回收站操作用于减少误覆盖与内容丢失，继续保留。

### 6.2 账号数据

`desk.db.credentials` 保存 id、title、username、password、website、notes 和 updated_at。密码是普通文本。账号读写接口不接收密钥，UI 不持有解锁状态。新增、编辑和删除均通过数据库接口完成。

### 6.3 旧版自动迁移

`legacy_credentials` 只读打开已有 `vault.db`，尝试读取本机可解开的旧账号并写入普通账号表；不创建或修改旧密钥。每个导入账号和 `legacy_credential_imports` 标记在同一事务提交。已导入的账号不再覆盖，删除账号时保留导入标记，避免重启后恢复已删除记录。旧文件损坏、旧密钥不可用或部分记录无法读取均不阻止其他功能；原文件保留。

### 6.4 查看与复制

密码始终以普通文本显示。账号详情使用整行字段、较大字号、清晰字形和不透明对话框，取消淡入透明动画。保留复制密码按钮，不设置隐藏选项、自动清空剪贴板或自动锁定。搜索按名称、用户名和网址匹配现有记录。

## 7 快捷路径与文件夹操作

### 7.1 快捷入口模型

快捷入口保存 id、target_kind、display_name、path_native、path_display、group_id、tags、sort_order、pinned、index_policy、created_at 和 updated_at。path_native 在 Windows 使用可逆 UTF16LE 字节表示，业务中还原成 PathBuf；path_display 仅用于显示，不得作为执行依据。

同一目标允许设置多个业务别名，但默认检测已有入口并提示；所选目录范围与卡片显示分开记录，移除一个别名不应误删其他入口的索引来源。保存路径是引用关系，不复制整个目录，也不改变原目录权限。

### 7.2 V1 操作集合

| 操作 | 具体行为 | 冲突与失败 |
| --- | --- | --- |
| 进入目录 | 在办公台分页列出真实子项 | 不存在与无权限分别提示 |
| 打开文件 | 用默认关联程序打开 | 无关联程序时提供定位文件 |
| 新建目录 | 当前目录创建单级目录 | 同名则提示，不自动合并 |
| 重命名 | 同目录更名，保留类型提示 | 同名不覆盖；大小写更名按平台处理 |
| 复制 | 支持文件和目录，展示进度 | 默认跳过并报告同名冲突，用户可另起名称 |
| 移动 | 同卷优先重命名，跨卷复制后验证再删源 | 验证或删除失败保留源并报告实际状态 |
| 删除 | 确认后送入系统回收站 | 不支持回收站的路径直接报错，不永久删除 |
| 系统打开 | 用资源管理器打开当前目录或定位文件 | 系统调用失败可复制显示路径 |

V1 不覆盖已有目标。批量任务逐项记录结果，部分成功必须展示成功、失败和跳过数量。移动目录时不能移到自身或子目录。回收站恢复由系统处理，应用不伪造成功的撤销功能。

### 7.3 路径与系统调用约束

所有操作通过系统路径 API 处理，不拼接 cmd 或 PowerShell 命令字符串。运行文件以系统关联打开；若目标是可执行文件或脚本，首次打开明确提示其类型，不默认自动执行索引到的程序。

文件浏览在一个已授权根目录下工作，UI 传递 root_id 和经检查的相对路径。服务拒绝绝对路径、父目录穿越、非法文件名、保留设备名、空字节及目标根之外的位置。新建文件需校验已存在的父目录；不能要求尚未创建的目标先 canonicalize。

Windows 路径不能只用字符串 starts_with 或一律转小写判断归属。使用路径组件和最终句柄路径验证，考虑长路径、盘符、卷身份及大小写敏感目录。V1 不遍历目录联接、符号链接和其他 reparse point；浏览时明确标识，递归操作拒绝跟随。

列目录时的检查不代替操作瞬间的检查。删除、移动和写入前重新验证父目录及文件身份，在平台支持时使用句柄和限制共享的方式缩小竞态窗口；不宣称完全抵御恶意本地进程实时替换目录。根目录删除和移动不开放，需通过资源管理器处理。

### 7.4 长任务与可恢复状态

递归复制先登记 FileJob，再逐项执行；数据流写入临时目标，关闭并确认后发布为最终名称。同名目标通过不覆盖的创建或重命名方式处理，避免检查后被其他程序创建所导致的覆盖。

取消复制时保留源文件，清理本任务未完成的临时产物，不删除用户已有内容。跨卷移动只有在拷贝、长度与内容校验成功且源文件状态未改变时才能删除该源文件；删除失败提示“已复制，源未移除”。重启不自动重放删除，未完成任务须重新核对后由用户选择继续。

## 8 搜索设计

### 8.1 搜索范围与隐私

| 数据类型 | 默认范围 | 检索内容 | 点击结果 |
| --- | --- | --- | --- |
| 快捷入口 | 已保存入口 | 别名、标签、显示路径 | 进入目录或打开文件 |
| 文件名 | 用户启用索引的根目录 | 名称、相对路径、扩展名 | 定位并打开 |
| 办公台文本 | 管理文档目录 | 标题及 UTF8 正文 | 打开内置编辑 |
| 外部正文 | 逐目录明确开启 | TXT 与 Markdown 正文 | 打开文件或编辑 |
| 账号条目 | 当前 Windows 用户的本机密码库 | 标题、用户名、网址 | 进入账号详情 |
| 物品清单 | 本机 SQLite 物品记录 | 名称、分类、数量、存放位置和备注 | 在物品页查看或编辑 |

不默认扫描全盘，不收集浏览器密码，不索引密码库、备份、临时文件、日志、target、node_modules 和 .git。排除办公台自身数据库和索引目录，避免索引递归。正文索引会在数据库中产生内容副本，开启外部正文索引前应明确说明。

顶部搜索框供各功能页复用，当前页面按自身数据字段筛选；已索引文件结果显示在快捷路径或文档页面。搜索是各功能内的筛选和定位能力，不设置独立结果页。

### 8.2 中文检索与查询规则

统一对索引文本和查询做一致的 Unicode 规范化；保留原文用于展示。三字符及以上的正文子串查询使用 FTS5 trigram，不能把 unicode61 等同于完整中文分词 [S3]。

一到两个字符的名称和正文查询采用后台参数化 LIKE 子串匹配，转义百分号、下划线和转义字符；该路径可能全表扫描，必须可取消。长查询超时后明确提示未搜索完成，并可继续，不以局部结果冒充全部命中。

默认输入作为字面量词处理，正确转义 FTS 查询语法，不直接拼接 MATCH 表达式。每次返回最多 100 条，按类别和相关性分组，可继续翻页。结果排序为精确名称、名称前缀、名称包含、正文相关性，再按更新时间和稳定 ID 排序。

### 8.3 索引更新与资源上限

索引器先枚举元数据，再在允许时抽取正文。初始仅为 UTF8 TXT 和 Markdown 建立正文索引，单文件上限建议 2 MiB；超过限制只索引名称并显示原因，不能静默截断后声称全文检索。其他编码先提示并在后续版本增加解码器。

监视器只提供变化线索，不能假定不会丢事件。通过 path_key、文件身份、大小和修改时间判断变化，必要时计算内容摘要；保存时提交索引事务。启动、目录重新连线或监视溢出时执行可取消的增量核对，支持手动重建。

根目录离线时保留旧记录并标记“来源离线”，不将临时不可访问视为全部删除。重命名和删除通过索引任务最终收敛。应用退出或用户取消后停止新的索引批次，不再发布迟到结果。

## 9 文档创建 编辑与保存

### 9.1 格式与编辑能力

台内新建文档直接打开标题与正文编辑区，正文以 UTF8 Markdown 文件保存到自管目录，内部文件名由 UUID 生成，标题单独保存在 SQLite。编辑和保存不要求选择本机路径；旧 Markdown、TXT 文件仍可用同一编辑器打开。点击添加不启动外部办公软件。

主动导出 Word 副本时，WordHandler 将当前编辑正文写入合法 OOXML ZIP 包，包含内容类型、关系和真实正文，并对 XML 特殊字符转义。导出不移动或替换台内原稿，不依赖模板；实际 Word/WPS 排版兼容性仍需目标软件验证。

DOCX 不在 V1 内置正文索引范围，也不在内置编辑器里转换后覆盖，避免破坏格式。外部软件打开后，应用只更新文档最近使用与变化状态。

### 9.2 保存一致性

每个编辑页维护 document_id、revision、persisted_revision、content、encoding、line_ending 和 external_fingerprint。保存任务携带 revision，同一个文件串行写入；旧 revision 保存结束不能把更新的修改标记成已保存。

正常保存流程是校验目标、检查外部变化、在目标同目录创建唯一临时文件、写入并同步数据、调用平台替换操作、提交文档记录，再异步刷新索引。Windows 的文件替换行为由适配器处理，并对 Word 占用等共享冲突进行测试 [S9]。

首次保存使用不覆盖的创建操作。不得用“先删除原文件再重命名”作为普通保存策略。磁盘写入成功但数据库更新失败时，保留真实文件并登记待核对状态；索引失败不回滚用户文档。具体断电耐久性受文件系统和硬件影响，需用故障测试验证，不能仅凭 rename 保证一切。

### 9.3 外部修改与草稿恢复

打开时记录文件身份、修改时间、大小及内容摘要。保存前发现外部变化，展示“重新加载”“另存为”和“明确覆盖”选项，默认不覆盖；确定覆盖后仍保留冲突前的应用草稿。

应用自管文档可以自动保存。首次用内置编辑器修改外部文本文件时确认编辑模式，告知修改将写回原位置，默认先手动保存；用户开启该文件自动保存后才允许后台写回。

草稿每 5 秒记录到 profile 的 recovery 目录，文件名不使用用户正文；草稿以普通文件保存，其保护级别与普通文档一致，不允许密码库数据写入草稿。重启后列出可恢复项，原文件已变化时恢复为新文件，不自动覆盖。

文档写入不与 SQLite 构成单一原子事务；以真实文件为内容事实来源，数据库记录和搜索索引是可核对、可重建的派生信息。

## 10 数据模型与迁移

### 10.1 目录与数据库

默认数据根目录为系统解析得到的 LOCALAPPDATA 下 PersonalDesk，不把路径固定写成某个用户名。目录下有 desk.db、documents、recovery 和 cache；升级用户可能保留旧版 vault.db。应用安装目录不保存用户数据，普通运行不要求管理员权限。

desk.db 保存普通账号、快捷入口、文档元数据、文件索引和任务。旧版 vault.db 仅用于只读迁移，迁移后的账号与标记统一在 desk.db 事务内提交。

### 10.2 主要数据表

| 数据库与表 | 关键字段 | 约束与说明 |
| --- | --- | --- |
| desk.credentials | id、title、username、password、website、notes、updated_at | 账号普通本地存储，无密钥参数 |
| desk.legacy_credential_imports | id | 记录已迁移账号；删除账号后保留，防止重复导入 |
| desk.shortcut_groups | id、name、sort_order | 被引用时删除需重新分组 |
| desk.shortcuts | id、root_id、group_id、kind、name、path_native、path_display、tags_json、sort_order、pinned | 以 ID 引用；标签校验后序列化 |
| desk.roots | id、path_native、path_display、identity、filename_index、content_index、state | 文件授权与索引来源 |
| desk.documents | path、format、title、last_opened | title 为独立显示标题；正文在文件中；旧表自动补充 title 字段 |
| desk.inventory_items | id、name、category、quantity、location、notes、created_at、updated_at | 个人物品记录；可按可见字段搜索 |
| desk.search_items | id、root_id、object_id、kind、path_key、title、path_display、body、modified_at、status | 正文仅限已授权普通文档 |
| desk.search_fts | title、path_display、body | FTS5 trigram 虚拟表，rowid 对应 search_items.id |
| desk.file_jobs | id、operation、state、progress、result_summary、created_at | 细项进度单独记录；不含凭据 |
| desk.settings | key、value_json、version | 只保存非敏感配置 |
| 两库 schema_migrations | version、checksum、applied_at | 顺序迁移并核对脚本摘要 |

所有普通表设置明确主键；关键关系启用外键。时间以 UTC 保存，界面按用户时区展示。必要索引包括 search_items(root_id, path_key) 唯一索引、shortcuts(group_id, sort_order) 和 documents(updated_at)。数据库文件权限继承当前用户私有数据目录并在安装测试中核查。

### 10.3 搜索表结构示例

以下 SQL 是设计片段，完整建表脚本仍需包含普通表、外键、索引和迁移事务。

```sql
CREATE VIRTUAL TABLE search_fts USING fts5(
    title, path_display, body,
    content='search_items', content_rowid='id',
    tokenize='trigram'
);
```

采用 external content 模式时，search_items 和 search_fts 必须同步；统一通过同一写入事务更新，并在迁移时先回填再 rebuild，避免已有数据不进入索引 [S3]。更新时使用旧值删除原 FTS 项，再插入新值；删除对象同步删除索引。为此建立插入、更新、删除的一致性集成测试。

### 10.4 版本迁移

启动先读取版本，旧版本按序迁移并在成功后更新版本号；遇到高于当前程序支持的数据版本，拒绝写入并提示升级。迁移前制作一致性快照，失败则停止打开而不是继续使用半迁移数据库。密码库负载版本、备份格式版本与数据库 schema_version 独立演进。

## 11 接口与扩展机制

### 11.1 应用层端口

| 端口 | 核心行为 | 可替换适配器 |
| --- | --- | --- |
| VaultRepository | 密文条目、账号包装数据、nonce 事务 | SQLite 实现、内存测试实现 |
| LegacyAccountImporter | 只读旧版账号并导入普通存储 | 仅迁移使用旧版解密兼容，不增加验证流程 |
| ShortcutRepository | 入口与分组读写 | SQLite 实现 |
| FileSystemPort | 列表、读取、创建、复制、移动、回收 | Windows 文件系统、故障模拟实现 |
| SystemOpenPort | 关联打开、定位文件、系统事件 | Windows Shell 实现 |
| DocumentFormatHandler | 能力说明、创建空白文件、读取和导出 | Markdown、TXT、DOCX 实现 |
| SearchProvider | 检索、取消、来源与分页 | 本地 FTS、账号内存搜索 |
| BackupStore | 加密备份读写、完整性校验 | 本地加密文件 |

### 11.2 Rust 接口形态示例

以下为接口草图，不是完整可编译代码。类型与细节应在对应 crate 中定义；实际同步文件 IO 由工作线程调用。

```rust
pub trait DocumentFormatHandler: Send + Sync {
    fn format_id(&self) -> &'static str;
    fn capabilities(&self) -> FormatCapabilities;
    fn create_blank(
        &self,
        output: &mut dyn std::io::Write,
    ) -> Result<(), AppError>;
}

pub struct FormatCapabilities {
    pub extensions: Vec<&'static str>,
    pub internal_edit: bool,
    pub external_edit: bool,
    pub body_search: bool,
}

pub struct FileTarget {
    pub root_id: RootId,
    pub relative: std::path::PathBuf,
}
```

DocumentService 负责授权、冲突检查和临时文件发布，格式处理器只往给定输出流写内容，不自行选择任意路径。可执行文件、数据库、网络和密码库能力不会因为注册一个文档处理器而自动授予。

### 11.3 扩展步骤

增加一种文件格式时，在 formats 下实现处理器，声明扩展名与能力，注册到 FormatRegistry，增加样例和兼容性测试，文档页根据 capabilities 显示功能。不能为没有实现读取的格式展示“内置编辑”。

增加 PDF 正文搜索时，只新增抽取器和相应 SearchProvider，设定资源限制及失败分类；不修改密码库密文结构。增加 macOS 或 Linux 时实现平台端口并测试文件路径、回收站、关联打开和锁屏行为；不把 cfg 条件散落在领域模型中。

V1 使用编译期显式注册。后续若需要用户安装第三方扩展，应采用独立进程或受限运行时、权限声明和版本化协议，不能直接加载任意 Rust 动态库并宣称 ABI 稳定。

## 12 备份 恢复与数据生命周期

### 12.1 备份内容

完整办公台备份包含 desk.db 和 vault.db 的一致性快照、办公台管理的 documents、用户选择的草稿及带摘要的清单。默认不包含缓存索引正文、日志、外部快捷目录和外部文件原件；界面须写明“快捷入口会备份，目标文件夹不会自动备份”。可在快照中删除派生搜索表数据，恢复后重建。

后续备份按普通本地归档设计，不增加密码或密钥流程。账号与文档一起包含在普通数据备份中；旧版保留文件可原样一并复制。

### 12.2 一致性与恢复

备份期间短暂暂停应用写入、停止新的索引批次、等待文件保存任务收敛，使用 SQLite Backup API 获得数据库快照，再收集自管文档，完成后释放屏障 [S10]。因文件和数据库不存在天然共同快照，屏障期间禁止自管文档写入并校验文件状态；检测到外部变更则重试该文档或使备份失败。

不能在 WAL 活跃时只复制单个 .db 文件冒充完整备份。备份完成必须检查返回值、完整性和归档摘要，失败不显示“已备份”。

恢复先在临时目录核对归档清单和数据库完整性，保留当前数据副本，再替换并检查普通数据是否可读；不要求口令或密钥。当前版本尚无备份恢复界面。

恢复到另一台电脑时，原快捷路径可能失效，进入批量重新定位流程；不自动创建同名空目录冒充原资料。卸载默认保留用户数据，删除数据必须另行明确选择。

### 12.3 清理与导出

每个模块提供当前功能及全部数据的 ZIP 导出，账号信息按普通 JSON 原样保存；不增加加密或密码流程。删除凭据后旧备份和存储介质上可能仍有旧版本，不能宣称 SQLite 删除等同于安全擦除。搜索历史默认不持久化；关闭正文索引后删除对应索引副本并说明普通文件、历史备份和 SSD 残留不受此动作完全控制。

## 13 错误处理与运行维护

| 场景 | 用户界面 | 后台处理 |
| --- | --- | --- |
| 旧版账号无法读取 | 提示原文件已保留，继续使用程序 | 不阻止新增账号或其他功能 |
| 文件占用 | 文件正被使用，可关闭外部程序后重试 | 原文件不删除，保存草稿 |
| 目录不存在 | 路径失效，重新定位 | 保留快捷入口与失效标记 |
| 文件权限不足 | 无权操作，可换目录 | 不自动要求管理员权限 |
| 磁盘空间不足 | 保存失败，可另存为 | 不标记已保存，保留可恢复文本 |
| 索引损坏 | 搜索暂不可用，可重建 | 不影响原始文档与密码库 |
| 数据库损坏 | 停止相关写入，选择备份恢复 | 保留原文件，输出脱敏诊断 |
| 批量操作部分失败 | 分项列出实际结果 | 持久化完成状态，不重放破坏性步骤 |

日志记录事件类型、任务 ID、耗时和错误类别，不记录密码、账号明文、文档正文或搜索词。默认不上传遥测。诊断包需用户主动导出，路径等个人信息先遮蔽，并允许预览内容。日志按大小轮转，保留策略可配置。

单实例运行：第二次启动聚焦已有窗口，避免两个进程同时修改编辑草稿或会话状态。异常退出后，先检查数据库和未完成任务，再展示恢复入口，不自动执行之前未完成的删除操作。

## 16 关键设计决策

### 16.1 原生 Rust 界面

采用 egui 与 eframe 以保持首版工程集中在 Rust，减少前后端构建链。代价是原生系统控件观感、辅助功能和输入法行为仍需验证；不把跨平台库能力等同于跨平台产品已完成。

### 16.2 文件内容与元数据分离

文档内容保存在用户可直接访问的普通文件中，SQLite 保存快捷关系、索引与状态。这样可以在办公台之外继续使用资料，也便于后续更换编辑器。代价是文件系统和数据库存在一致性窗口，需要核对与可重建索引。

### 16.3 账号以方便使用为优先

账号采用普通本地存储，不依赖密钥，不提供密码隐藏。旧版读取兼容与日常 CRUD 分离，只有升级迁移路径保留解密代码。

### 16.4 可扩展但不提前平台化

以端口、格式注册和搜索来源注册满足扩展性，V1 仍为单个本地应用。稳定的领域模型、明确版本和故障处理优先于动态插件市场、微服务或复杂通用框架。

## 17 开发交付清单

开发完成应提供 Rust 源码与锁文件、工具链配置、Windows 安装包或便携包、数据库迁移、测试报告、依赖与许可证清单、用户操作说明、备份恢复说明和本开发文档的更新版。

代码评审重点核对：UI 是否绕过用例直接操作系统；密码是否进入日志或普通搜索；文件任务是否默认覆盖或永久删除；保存状态是否与真实 revision 一致；新增格式是否仅需新增处理器及注册；恢复后是否可安全继续写入。

### 19.2 本机运行

项目面向 Windows x64。由源码构建需要 Rust 1.95 或更新版本；当前工具链配置使用 stable GNU target。Windows GNU 构建还需要可用的 MinGW 编译器和资源工具。

在项目根目录运行以下命令：

```powershell
cargo run --release
```

运行检查：

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

在含中文字符的项目路径下使用 MinGW 时，应将 Cargo 构建目录放在纯英文路径，例如：

```powershell
$env:CARGO_TARGET_DIR = 'C:\personal-desk-target'
cargo build --release
```

数据位于 `%LOCALAPPDATA%\PersonalDesk`。`desk.db` 保存普通账号、快捷路径、物品、文档记录和索引；文档与恢复草稿是普通文件。已有 `vault.db` 仅作旧版迁移来源，只读保留。新版本不创建密码库或密钥。

## 20 标签、双击与外部拖入（2026-10-19）

- 快捷路径内的文件单击选中、双击提交系统打开请求，目录仍单击进入。文件快捷入口和文件搜索结果同样支持双击；台内文档继续点击进入编辑器。

file_drop::client_position 在发生文件悬停或拖入事件时调用 GetCursorPos、ScreenToClient，并用 egui 实际 pixels_per_point 转成逻辑坐标。Windows OLE DragOver 不产生普通鼠标移动事件，因此不能用上一次 egui 指针位置决定投递目标。悬停期间持续重绘，显示实际目标边框和简短目标名称。

file_transfer 使用 IShellItem::BindToHandler(BHID_DataObject) 构造 Shell IDataObject。复制按钮、右键复制和 Ctrl+C 调用 OleSetClipboard/OleFlushClipboard，剪贴板包含真正的文件对象，可在资源管理器粘贴；向外拖拽使用 SHDoDragDrop，Shell 提供默认拖拽源与图像，只允许复制效果。每次 OLE 初始化与释放平衡，原文件路径不通过命令行拼接。原生拖拽循环结束后清理 egui 拖动/指针状态，避免取消后残留按下状态。
