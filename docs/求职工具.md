# BOSS 直聘、官网投递与接码

三个工具在“小工具”中直接打开，运行逻辑由 Rust 编译进同一个个人办公台程序。招聘网站的页面操作使用浏览器本身的 JavaScript；无需安装 Python、Node 或原工具的命令行依赖。需要本机 Chrome 或 Edge。

## 首次使用

1. 在任一个求职工具面板中打开“资料与设置”，选择“导入原三个工具的资料和队列”，选择包含三个原目录的个人办公台文件夹。
2. 原始资料、队列、配置、密钥保留。原待投队列导入后默认跳过；确认旧工具任务停止、网页账号正确后再将需要的项目设为待投。
3. 在 BOSS 页点击“登录 BOSS”。官网工具使用自己的专用浏览器；两个浏览器配置分别保存，不复用旧登录态。

## BOSS 直聘

按关键词、城市、经验、学历和工作类型搜索，加载更多岗位，查看详情或加入队列。可以设置招呼语、简历图片、每日上限、随机间隔和允许投递时段。支持单岗位预检、确认发送、按队列批量执行、停止队列及查看记录。

发送前须在界面确认本人账号及旧队列停止；实际发送仍有单独确认。发送结果不明确时记为待核验，文字已发而图片未确认时记为部分发送；两者均禁止自动重试。薪资遇到网站加密字体时显示“需在网页核验”，不推测数值。

## 官网投递

打开招聘网页，完成登录，识别表单。资料沿用原 Markdown 格式，支持基本信息、求职意向、教育、工作、项目等标签别名。填写支持标准输入、下拉、单选及常见自定义选项；同源 iframe 和开放的 Shadow DOM 沿用原工具的识别辅助代码。资料中的“待补充”和含义不明确的字段跳过，不覆盖网页现有值。多个经历中无法确定的字段由本人核验和填写。

可上传资料中唯一匹配的附件；身份证正反面材料不自动上传。可选择推进明确的“下一步”，最多八步，并在最终提交前停止。跨域表单、未匹配的自定义控件、扫码和滑块需要在浏览器完成。

请先在网页检查并勾选相关条款，完成必填项，再点击“提交预检”。正式提交须勾选界面确认并再次确认执行。预检记录只保存页面摘要的哈希；五分钟内页面地址和字段内容保持一致才能提交。每日最多 20 次，每次至少间隔 30 秒，结果不明时阻止自动重试。

## 接码

启动本地服务后，可复制 Webhook 地址到安卓 SmsForwarder；支持原 JSON 和表单请求。沿用旧 token 时手机端无需更换 token，但电脑地址或端口变化后需更新 URL。默认自动选择私有局域网地址，无可用地址时回退到回环地址。端口占用时先检查旧服务。

短信请求需鉴权，最大 64 KB，每个来源每分钟最多 60 次，时间戳偏差超过 600 秒拒绝。验证码在内存保留 120 秒，状态和响应不回显正文。取码接口限制本机访问；官网工具在进程内读取后直接填写，模型、日志和资料文件不接收验证码。密钥和 URL 文件限制为当前 Windows 用户访问。关闭面板后继续接收，退出办公台时停止。

## 数据与验证范围

数据位于办公台当前数据目录的 `hiring/`：`hiring.sqlite` 保存队列、尝试记录和限额，`settings.json` 保存配置，`profile.md` 保存资料；登录态、接码文件也位于此目录。正式程序和 ZIP 不包含这些个人数据。

本版本以已发布的 0.15.14 源码为基线，保留多层图书嵌套、PDF 转图片、Excel 合并、图书目录与缩放等功能。测试覆盖本地表单、附件上传、接码、预检摘要、提交成功识别、导入事务、去重和界面入口。真实 BOSS/公司网页会变化，真实账号投递需要用户登录后核验，不把本地模拟测试计为真实网站验收。

原工具的 Python CLI、MCP stdio 入口和旧运行脚本作为原始源码保留。新版用同一 EXE 的 `--mcp` 模式提供 Rust 原生 MCP 接口，供 AI 助手调用；详见[求职 MCP 服务](求职MCP服务.md)，不再依赖原 Python 入口。BOSS 页面辅助代码改编自所提供 BossHunter 源码，其 PolyForm Noncommercial 1.0.0 许可全文见 `assets/hiring/BossHunter-LICENSE.txt`，发布包同时附带该许可。
