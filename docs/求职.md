# 求职

侧栏“求职”包含“网站”和“投递记录”两个页面，宫格和列表两种视图共用搜索、数据与操作。

“网站”自动汇总已保存的校招岗位 / 公告、BOSS 队列和历史投递涉及的网址，显示公司、岗位、城市、来源与网址。可按公司、来源和关键词筛选，并添加、编辑、删除自己的公司 / 岗位网站记录。删除需要确认；数据保留删除标记，过期编辑窗口不能覆盖新修改。

点击“校招搜索”运行新搜索，结果保存在同一个 desk.db，页面每 3 秒刷新。点击岗位展开说明，点击网址查看原文。没有公开网申地址时保留公告网址，需要从原文核对投递方式。

“BOSS 工具”和“官网投递工具”打开既有投递工具，带入岗位、公司与网址。打开页面、保存网站和加入列表不会发送招呼或提交表单。实际操作沿用已有的预检、确认、去重和限额保护。

“投递记录”直接读取原数据目录 hiring/hiring.sqlite 的 attempts 表，不建立另一份投递台账。BOSS 的 sent 显示为“招呼已发送”，官网 sent 显示为“已提交”；partial 显示为“部分发送”，reserved / running / ambiguous 显示为“待核验”。旧资料导入的记录保留原备注。不会按公司名把同公司的其他岗位标为已投递，网址可以精确匹配时才关联状态；ATS 不同哈希路径保持区分。原校招工具的人工“已投递”标记仍仅作为人工标记。

打开求职页面只读投递数据库，不会重置正在执行的队列。投递记录按时间倒序，分页显示完整记录；MCP 和桌面的变更都会刷新显示。新加的网站记录保存在 desk.db 的 jobhunt_sites 表，编辑采用版本检查，删除为软删除。

页面“导出”可备份公司 / 岗位网站、校招结果、投递记录 JSON 和原 hiring.sqlite 快照；全部数据备份也包含这些信息。

同一个程序支持无界面的公开网站搜索：`个人办公台.exe --campus-search [绝对数据目录] [搜索条件.json] [结果报告.json]`。使用与桌面相同的 Rust 搜索和保存逻辑，分批保存结果，保留收藏、已投递与忽略状态。信息源可能受登录、网络和页面结构限制；报告按来源记录结果数和失败原因。
